# AGENTS.md — Terminal

> 内嵌 libghostty 真终端模块。本文就近覆盖根 `AGENTS.md`。

## 职责

把 libghostty（`vendor/GhosttyKit.xcframework`）嵌进 `NSView` 跑真 PTY shell，并通过 `TerminalEngine` 协议向业务层暴露。
S2 完成冒烟验证；S8 补齐协议抽象并将终端嵌入主窗口底部面板；S9 新增 `writeText` 文本注入能力（Context Bridge 基础）。S27 补齐完整键盘/鼠标/IME/剪贴板事件处理，终端输入兼容性已对齐标准终端。

## 目录结构

- `TerminalEngine.swift` — 协议定义：多 session API（`createSession(cwd:) -> UUID` / `closeSession` / `terminalView(for:)` / `writeText(_:to:)` / `onCwdChange` / `onTitleChange` / `onPathLinkClick`），业务层唯一依赖
- `GhosttyTerminalEngine.swift` — 协议实现：管理多个 `GhosttySurfaceView` 实例（`[UUID: GhosttySurfaceView]` 字典），延迟创建 surface，关闭时释放；`pendingBuffers`（`PendingTextBuffer`，条数/字节上限）解决 surface 未就绪时 `writeText` 丢失，`onSurfaceReady` flush、超时 token 化可取消、surface 创建失败经 `onSurfaceFailed` 立即丢弃并 `onPendingDropped` 上报；`handleSurfaceClose` 经 `exitedSessionIDs` 遍历全部已退出 surface；通过 `GhosttyApp.registerPwdHandler` 订阅 cwd 变化；通过 `GhosttyApp.registerTitleHandler` 订阅 OSC title 变化（`GHOSTTY_ACTION_SET_TITLE`）
- `PendingTextBuffer.swift` — `writeText` pending 缓冲纯值类型：FIFO + 条数 64 / 字节 256KB 上限（超限丢队头最旧、单条超限仍接受）+ `SurfaceFailureReason` / `PendingDropReason` 枚举
- `TerminalSession.swift` — 会话值类型（id, title, cwd, currentCwd, isManuallyRenamed）+ `TerminalTabState`（Codable，用于跨重启 tab 恢复，向后兼容缺省 `isManuallyRenamed=false`），SwiftUI 可 ForEach
- `PathLinkHoverTracker.swift` — ⌘悬停决策纯状态机（`update(cmdHeld:cell:)` → clear/keep/evaluate + `invalidate()`），视图只执行动作；时序语义单测见 `PathLinkHoverTrackerTests`
- `ShellIntegration.swift` — zsh/bash shell integration：ZDOTDIR 注入 OSC 7 precmd/chpwd hook + OSC 2 title precmd/preexec hook（zsh），PROMPT_COMMAND 注入 OSC 7 + OSC 2 title（bash）
- `TerminalTabBar.swift` — Finder-first 模式横向 Tab 栏 SwiftUI 视图：tab 切换 / 新建（+按钮）/ 关闭（×按钮）/ 双击重命名 / 拖拽重排（`onReorder: (UUID, Int) -> Void`，由宿主透传到 `WorkspaceController.reorderTerminal(source:to:)`，仅重排 per-window `TerminalSessionStore.sessions` 数组顺序，不重建 PTY / surface，active session 不变）。视觉对齐 NSWindowTab 设计 token（`TerminalTabStyle` 圆角 8pt / 间距 4pt / `controlBackgroundColor` 活跃态 / hover 才显关闭按钮 / 13pt 字号 / 邻居 spring 让位 + drop 弹性归位）。API 为 data+closure（非 binding），显示当前 workspace window 的终端 session 子集
- `VerticalTerminalTabBar.swift` — Terminal-first 模式纵向 Tab 列表（外部传入宽度，可拖动 100–300pt，36pt 项高）：标题 + cwd 副文本 + 左侧 2pt accent 活跃指示 + 底部固定新建按钮 + 拖拽重排（同 `TerminalTabBar.onReorder`，方向参数化按 y 半区判 top/bottom）
- `TerminalPanelView.swift` — `NSViewRepresentable` 多 session 容器：container NSView + `isHidden` 切换活跃 surface + 焦点跟随。传入 per-window `TerminalSessionStore.allIDs` 避免切 session 时误删其他 session 的 surface subview。S32 起每个 NSWindow workspace 独立持有 store，session 不跨 window 共享
- `GhosttyApp.swift` — 进程级 runtime 单例：`ghostty_init` + `app_new` + runtime callbacks + `wakeup`→合并主队列 `app_tick` + `action_cb` 处理 `GHOSTTY_ACTION_PWD`/`SET_TITLE`（多 handler 注册）/`SHOW_CHILD_EXITED`（子进程退出 → post `ghosttySurfaceDidClose` 关 tab + `return true` 抑制 "press any key" overlay）/`OPEN_URL`（core 检测到的 URL ⌘Click → `openableURL(from:)` 纯函数校验 scheme → file:// 经 `registerFileURLHandler` 改道 Locate（ADR-0003 绝不打开），其余 `NSWorkspace.open`）
- `GhosttySurfaceView.swift` — `CAMetalLayer`-backed `NSView`：surface 生命周期 + 尺寸/缩放/display 同步 + 完整键盘/鼠标/IME 事件转发 + `initialCwd` 可配置 + `onSurfaceReady` 回调（`createSurface` 成功后触发）+ `onSurfaceFailed` 回调（app 未初始化 / `ghostty_surface_new` 返回 nil 时触发，供 engine 立即丢弃 pending）+ 读取 Settings（shell/font size）+ shell integration env vars 注入 + `config.userdata` 指向 self（供 clipboard 等 runtime callback 通过 surface userdata 反查 view）+ `forwardedKeyPresses: Set<UInt16>` 追踪实际发给 Ghostty 的 PRESS（keyUp/monitor 仅对有记录的发 RELEASE，resignFirstResponder 清空并逐个释放）+ `pressedMouseButtons: Set<Int>` 追踪 Ghostty 接受的鼠标 PRESS（Up 仅对有记录的发 RELEASE）+ `resignFirstResponder` 释放残留修饰键 + outstanding 非修饰键 + ⌘Click Path Link 拦截（`gridCell(atLocal:)` 像素→格子换算 `ghostty_surface_size` + `pathLink(atCell:)` 读行 `ghostty_surface_read_text` → `ContextBridge/PathLinkDetector` → `onPathLinkClick` 回调；命中不进 core、`suppressNextLeftMouseUp` 配对）+ ⌘悬停反馈（`updateHover` 格子级缓存 → pointingHand + 浮层显示解析后绝对路径，松 ⌘/移出/失焦/滚动即清，浮层 `hitTest nil` 纯展示）
- `TerminalPreferences.swift` — 终端偏好单实例（`@Observable nonisolated`，与 `Workspace/WorkspacePreferences` 并列，专管终端外观/行为）：shell/customShellPath（仅影响新建终端）+ fontSize/scrollback/fontFamily/fontStyle/useLigatures/fontThicken/useNonASCIIFont/nonASCIIFontFamily/cursorStyle/padding/opacity/blur/copyOnSelect（外观项）。每属性 `didSet` 持久化裸 UserDefaults key；外观项额外 post `.terminalAppearanceDidChange` 触发热重载。`nonisolated` 因被 nonisolated 的 `GhosttyApp` 读取
- `TerminalConfigWriter.swift` — 偏好 → ghostty 配置文本（`nonisolated`）：内置 Monokai Pro Light 固定配色（hardcoded `themeLines`）+ font-family/font-style/font-size/font-feature（连字）/font-thicken/font-codepoint-map（non-ASCII）/cursor-style/window-padding/background-opacity/background-blur/copy-on-select/scrollback-limit 展开成 `key = value` 行，`writeCurrent()` 原子写 `NSTemporaryDirectory()/PathDeck/runtime.conf`。透传唯一通道（xcframework 无逐键 setter）。scrollback「行」按 ~1KB/行换算成 ghostty 字节 `scrollback-limit`
入口：Finder-first 模式底部 Terminal Panel + Terminal-first 模式全屏终端（⌃\` 三态循环切换）。S32 起每个 NSWindow workspace（即每个 `WorkspaceController`）独立持有 `TerminalSessionStore`（session 数组）+ `WorkspaceViewState`（含 anchor cwd 绑定），session 不跨 window 共享；`GhosttyTerminalEngine` 全 app 唯一单实例由 `WorkspaceManager` 持有，反查 owner controller 派发 close/cwd/title 回调。

## 构建前置

`vendor/GhosttyKit.xcframework` 不进 git。clone 后须先按根 `AGENTS.md` 的 libghostty recipe 重建，否则链接 undefined symbol。

链接配置（pbxproj，cmux 生产验证）：`FRAMEWORK_SEARCH_PATHS = $(PROJECT_DIR)/vendor`；`OTHER_LDFLAGS = -lc++ -framework Metal -framework QuartzCore -framework IOSurface -framework UniformTypeIdentifiers -framework Carbon`。桥接走 `import GhosttyKit`（xcframework module，无 bridging header）。

## 模块规范

- **协议已补齐（S8）**：业务层（`Workspace/WorkspaceRootView` / `Workspace/WorkspaceController` 等）只依赖 `TerminalEngine` 协议，不 `import GhosttyKit`。libghostty C 符号限于 `GhosttyApp.swift`、`GhosttySurfaceView.swift` 与 `GhosttyTerminalEngine.swift`（后者仅持 `ghostty_surface_t` 句柄做反查/handler 签名 + 个别查询型 C 调用，不做渲染/输入类调用）。`GhosttyTerminalEngine` 是唯一桥接点——后续切换到 SwiftTerm 只需新增一个 `SwiftTermEngine` 实现。
- 渲染由 libghostty 内部 CVDisplayLink 自驱，**本模块从不调 `ghostty_surface_draw`**。宿主义务：`CAMetalLayer`-backed NSView + `set_display_id` + 创建/resize 后 `refresh` + `wakeup`→主队列 `app_tick`。
- surface 必须在 view 挂上 window 后再建（gate `window != nil`），否则黑屏。
- runtime callbacks 是 `@convention(c)`；app 级 userdata = `GhosttyApp`（`passUnretained`）。`read_clipboard_cb` 读 `NSPasteboard.general` → `ghostty_surface_complete_clipboard_request(..., confirmed: false)`（不跳过 Ghostty 的 unsafe paste 检查；第一个 `void*` 参数是 surface userdata → `Unmanaged<GhosttySurfaceView>` 反查 → `view.surface`，无全局状态依赖）；`write_clipboard_cb` 遍历 `ghostty_clipboard_content_s` 数组按 MIME 映射 `PasteboardType`（`text/plain`→`.string`，`text/html`→`.html`）写 `NSPasteboard.general`；`confirm_read_clipboard_cb` auto-deny（OSC 52 读剪贴板拒绝）。`close_surface_cb` 发 `ghosttySurfaceDidClose` 通知。
- terminfo：冒烟经 surface `env_vars` 注入 `TERM=xterm-256color`，不依赖 `GHOSTTY_RESOURCES_DIR`。预编译 xcframework 不含 zig-out 的 `xterm-ghostty` terminfo / shell-integration / themes，M1 须单独获取。
- `read_clipboard_cb`：**本仓库当前 xcframework 正确导入为返回 `Bool`，直接赋字面闭包**。若换 GhosttyKit 构建把它导入成 `Void`，改用顶层函数 + `unsafeBitCast`（cmux 模式）。

## 依赖关系

依赖 GhosttyKit（vendor xcframework）；被 `Workspace/WorkspaceRootView`（终端面板/纵向 tab bar）与 `Workspace/WorkspaceController`（terminal lifecycle 包装）引用，通过 `TerminalEngine` 协议间接依赖，不直接 `import GhosttyKit`。

## 验证

- 自动：`PathDeckTests/GhosttyLinkTests`（`ghostty_info()` 链接冒烟）+ `PathDeckTests/GhosttyOpenURLTests`（OPEN_URL 的 URL 解析决策）+ `PathDeckTests/GhosttyGridCellTests`（像素→格子换算，含 padding/scale/翻转/越界）+ `PathDeckTests/PathLinkHoverTests`（浮层定位 clamp + 悬停状态机时序）+ `PathDeckTests/LocateBehaviorTests`（真窗口：Locate 文件选中不夺焦/目录进入/reveal 默认夺焦）+ `build`。
- 真窗口测试等 `DispatchQueue.main.async` 结果必须 `await`（如 `Task.sleep`）让出 MainActor：测试体本身是 main queue 正在执行的 job，`RunLoop.run(until:)` 只泵 runloop source（SwiftUI 渲染会跑），drain 不了 main queue，async 块永远排不上。
- GUI 验证（渲染 + 键盘回显）人工在 Xcode Run 主窗口终端面板走查。
