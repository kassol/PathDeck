# S22：CLI Helper (`pathdeck`)

> 状态：Done
> 前置：S18 系统入口（URL Scheme + AppRouter 基础设施已就位）
> 目标：从终端一行命令唤起 PathDeck，闭合 M5 最后一条外部入口

## 背景

FinderSync Kill 后，外部入口矩阵为 Services + URL Scheme + Open With + **CLI helper**。前三者已在 S18 落地，CLI helper 是唯一缺口。用户在终端工作时，`pathdeck .` 打开当前目录是最自然的入口——类比 `code .`（VS Code）、`subl .`（Sublime Text）。

## Scope

- `pathdeck` 命令行工具：解析子命令 + 路径，构造 `pathdeck://` URL，调 `/usr/bin/open` 唤起 App
- 菜单项 "Install Command Line Tool…"：将 CLI 二进制安装到 `/usr/local/bin/pathdeck`
- 单测覆盖 CLI 参数解析 + 路径解析逻辑

## Non-scope

- 不做 CLI → App 的自定义 IPC（XPC / Mach port / 分布式通知）——URL Scheme 已覆盖全部路由
- 不做 tab completion / man page（后续按需加）
- 不做 `pathdeck --version` 版本查询（无 App 通信通道拿版本号，后续可加）
- 不解除 `terminal` 子命令的确认弹窗——CLI 仍经 URL Scheme 传递，安全模型与外部 deep-link 一致，v1 接受

## 命令设计

```
pathdeck                     # 在 PathDeck 中打开 cwd
pathdeck <path>              # 智能路由：目录 → open，文件 → reveal
pathdeck open [path]         # 打开目录（默认 cwd）
pathdeck reveal <path>       # 在 PathDeck 中定位文件
pathdeck terminal [path]     # 在指定目录打开终端（默认 cwd，弹确认）
pathdeck help                # 用法说明
```

### 路径处理

- 相对路径 → 基于 cwd 解析为绝对路径
- `~` → 展开为 `$HOME`
- symlink → 不解析，保留用户输入的路径（与 `standardizedFileURL` 行为一致）
- 路径不存在 → stderr 报错，exit 1

### 退出码

| 码 | 含义 |
|----|------|
| 0 | 成功（URL 已发送给系统） |
| 1 | 参数错误或路径不存在 |
| 2 | 打开 URL 失败（PathDeck 未安装等） |

### URL 构造

直接复用 S18 的 URL Scheme 格式：

```
pathdeck://open?path=/absolute/path
pathdeck://reveal?path=/absolute/path
pathdeck://terminal?path=/absolute/path
```

路径由 `URLComponents` + `URLQueryItem` 自动 percent-encode，不手动编码。

## 实现方案

### 方案选型

**选定：Swift 命令行工具（Foundation-only，无外部依赖）**

理由：
- `URLComponents` / `FileManager` 处理路径编码和校验，比 shell 脚本边界情况更少
- 项目全栈 Swift，不引入新语言
- 无 ArgumentParser 依赖——3 个子命令的 args 解析用 `CommandLine.arguments` 直接处理
- 不 import AppKit——用 `Process("/usr/bin/open", url)` 调起 URL Scheme，二进制保持轻量

淘汰：
- Shell 脚本：路径含空格 / 特殊字符的 URL 编码需调 python3 或 perl，边界情况多
- ArgumentParser：添加 SPM 依赖只为 3 个子命令，过重

### 文件结构

```
CLI/
  main.swift          # 入口：参数解析 + 路径校验 + URL 构造 + open
  CLICommand.swift       # 可测试纯函数：resolveAction(_:) → (action, url) / error
```

将参数解析 + 路径解析逻辑抽到 `CLICommand` 的纯函数中，`main.swift` 只做 IO（读 args、调 `Process`、写 stderr）。单测直接测 `CLICommand`，不需要起进程。

### Xcode 工程变更

1. 新增 **Command Line Tool** target `pathdeck-cli`，product name = `pathdeck`
2. Sources：`CLI/main.swift` + `CLI/CLICommand.swift`
3. Deployment target：macOS 26.5（同主 App）
4. 主 App target 增加 **Copy Files** build phase：将 `pathdeck` 二进制拷到 `Contents/Resources/`
5. `CLI/` 目录内 `.swift` 文件属于 `pathdeck-cli` target，不属于 `PathDeck` app target

### "Install Command Line Tool…" 菜单

PathDeckApp.swift 的菜单栏（`CommandMenu` 或 `CommandGroup`）新增一项：

```
PathDeck 菜单 → Install Command Line Tool…
```

行为：
1. 取 `Bundle.main.url(forResource: "pathdeck", withExtension: nil)` 获得 app 内嵌二进制
2. 目标路径 `/usr/local/bin/pathdeck`
3. 若 `/usr/local/bin/` 不存在，`FileManager.createDirectory` 创建
4. 若目标已存在且是目录，拒绝覆盖并提示用户手动删除
5. `copyItem` 到同目录临时文件 → `setAttributes(.posixPermissions: 0o755)` → `replaceItemAt` 原子替换
6. 若权限不足（`/usr/local/bin` 不可写），提示用户手动执行 `sudo cp <shell-escaped source> /usr/local/bin/pathdeck`（源路径经 `ShellEscape.escape` 处理）
7. 成功后 `NSAlert` 提示 "已安装到 /usr/local/bin/pathdeck"

不用 symlink 而用 copy：symlink 指向 app bundle 路径，app 移动后断链；copy 是独立二进制，不依赖 app 位置。代价是升级后需重新 Install，但 CLI 逻辑几乎不变（只是 URL 构造），频率极低。

### 单测

在 `PathDeckTests/` 新增 `CLICommandTests.swift`，测试 `CLICommand` 纯函数：

| 用例 | 输入 | 期望 |
|------|------|------|
| 无参数 | `[]` | `(.open, cwd)` |
| 目录路径 | `["/tmp"]` | `(.open, /tmp)` |
| 文件路径 | `["/tmp/a.txt"]`（需文件存在） | `(.reveal, /tmp/a.txt)` |
| `open` 子命令 | `["open"]` | `(.open, cwd)` |
| `open` + 路径 | `["open", "/tmp"]` | `(.open, /tmp)` |
| `reveal` 子命令 | `["reveal", "/tmp/a.txt"]` | `(.reveal, /tmp/a.txt)` |
| `reveal` 无路径 | `["reveal"]` | error：缺少路径 |
| `terminal` 子命令 | `["terminal"]` | `(.terminal, cwd)` |
| `terminal` + 路径 | `["terminal", "/tmp"]` | `(.terminal, /tmp)` |
| `terminal` + 非目录 | `["terminal", "/tmp/a.txt"]` | error：不是目录 |
| 不存在路径 | `["/nonexistent"]` | error：路径不存在 |
| 相对路径 | `["open", "relative"]` | 解析为 cwd/relative |
| `~` 展开 | `["open", "~/Desktop"]` | 展开为 $HOME/Desktop |
| `help` | `["help"]` | help 标记 |
| 未知子命令 | `["unknown"]` | 当作路径处理（智能路由） |
| URL 构造 | action + path | 验证 percent-encode 正确（空格、中文、#） |

测试用临时目录隔离文件操作，通过注入 cwd 参数避免依赖进程真实工作目录。

## 风险

| 风险 | 影响 | 应对 |
|------|------|------|
| `/usr/local/bin` 不存在或不可写 | Install 失败 | 提示手动 `sudo` 命令 |
| App 升级后 CLI 行为漂移 | 旧 CLI 构造的 URL 格式不兼容 | URL Scheme 格式已冻结（S18），几乎不会变 |
| `terminal` 每次弹确认 | CLI 用户觉得烦 | v1 接受；后续可加签名 token 机制绕过 |
