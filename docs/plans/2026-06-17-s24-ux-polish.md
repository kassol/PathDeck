## P0：文件列表最后一列截断

### 问题

4 列固定宽度（280+170+90+150=690pt），无 autoresize 策略。窗口宽度 < 690 时 Kind 列消失，且用户无法手动拖宽。

### 方案

`FileTableView.swift` 的 `makeNSView` 中：

1. 设置 `tableView.columnAutoresizingStyle = .lastColumnOnlyAutoresizingStyle`——最后一列自动填满剩余空间，窗口缩窄时最后一列跟着缩但不消失
2. 各列设 `minWidth` / `maxWidth` 约束：Name minWidth=120, Date minWidth=100, Size minWidth=60, Kind minWidth=60
3. 设置 `tableView.autoresizesSubviews = true`（默认已是，显式确认）

```swift
// FileTableView.swift makeNSView, column setup 后追加
tableView.columnAutoresizingStyle = .lastColumnOnlyAutoresizingStyle

// 各列 minWidth
for column in tableView.tableColumns {
    switch column.identifier.rawValue {
    case Coordinator.nameColumn:   column.minWidth = 120
    case Coordinator.dateColumn:   column.minWidth = 100
    case Coordinator.sizeColumn:   column.minWidth = 60
    case Coordinator.kindColumn:   column.minWidth = 60
    default: break
    }
}
```

### 验证

- 窗口拉窄到最小，4 列均可见（Kind 列压缩到 60pt 但不消失）
- 窗口拉宽，Kind 列自动填充剩余空间
- 用户可手动拖动列分隔线调整各列宽度

## P1-a：垂直 tab 分隔线拖动

### 现状

`ContentView.swift:270-298` Terminal-first 布局：`VerticalTerminalTabBar`（hardcoded `width: 140`）+ `Divider()` + `TerminalPanelView`。Divider 不可交互。

水平 Terminal divider（`TerminalDividerView`，`ContentView.swift:505-531`）已有完整拖动实现，可复用模式。

### 方案

1. 新增 `VerticalDividerView`（类似 `TerminalDividerView`，方向改为左右拖动）
2. `ContentView` 新增 `@State private var verticalTabWidth: CGFloat = 140`，传入 `VerticalTerminalTabBar` 替代 hardcoded 140
3. 拖动范围 `100...300`，cursor 改为 `resizeLeftRight`
4. `VerticalTerminalTabBar` 的 `.frame(width:)` 改为外部传入参数
5. 宽度纳入 `WindowLayoutState` 持久化

```swift
// ContentView.swift — terminalFirstContent()
@State private var verticalTabWidth: CGFloat = 140

HStack(spacing: 0) {
    VerticalTerminalTabBar(...)
        .frame(width: verticalTabWidth)

    VerticalDividerView(
        width: $verticalTabWidth,
        minWidth: 100,
        maxWidth: 300
    )

    TerminalPanelView(...)
}
```

```swift
// ContentView.swift — 新增
private struct VerticalDividerView: View {
    @Binding var width: CGFloat
    let minWidth: CGFloat
    let maxWidth: CGFloat

    var body: some View {
        Rectangle()
            .fill(Color(nsColor: .separatorColor))
            .frame(width: 4)
            .contentShape(Rectangle())
            .onHover { hovering in
                if hovering { NSCursor.resizeLeftRight.push() }
                else { NSCursor.pop() }
            }
            .gesture(
                DragGesture(minimumDistance: 1)
                    .onChanged { value in
                        width = max(minWidth, min(value.location.x, maxWidth))
                    }
            )
    }
}
```

### VerticalTerminalTabBar 改动

移除内部 hardcoded `.frame(width: 140)`，width 由外部 `.frame(width:)` 控制（已是这样用的，只需删除 `VerticalTerminalTabBar.swift:44` 的 `.frame(width: 140)`）。

### 持久化

`verticalTabWidth` 加入已有的 `WindowLayoutState`（`ContentView.swift` 中 `@AppStorage` 或 UserDefaults 持久化的窗口布局状态），与 `terminalPanelHeight` 同级。

### 验证

- 拖动分隔线可调整垂直 tab bar 宽度（100–300pt）
- cursor 变为左右箭头
- 重启后宽度恢复
- Tab 内容（标题、cwd）在不同宽度下正常显示（truncation 而非溢出）

## P1-b：终端 tab 标题跟随 shell 动态更新

### 现状

- `GhosttyApp.swift:104-114` 已处理 `GHOSTTY_ACTION_SET_TITLE`，分发给注册的 titleHandlers
- `GhosttyApp.swift:45-48` 有 `registerTitleHandler()` 方法
- **但从未被调用**——`GhosttyTerminalEngine` 只注册了 pwdHandler，没注册 titleHandler
- 终端标题仅在创建时设为 "Terminal" / "Terminal N"，此后只能手动双击重命名

### 方案

沿用 pwdHandler 的模式，在 `GhosttyTerminalEngine` 中注册 titleHandler：

1. **TerminalEngine 协议**：新增 `var onTitleChange: ((UUID, String) -> Void)? { get set }`
2. **GhosttyTerminalEngine.init()**：注册 titleHandler（与 pwdHandler 同级）
3. **GhosttyTerminalEngine**：新增 `handleTitleChange(surface:title:)` 方法，通过 surface 反查 sessionID，调用 `onTitleChange`
4. **ContentView / TabManager**：在 `terminalEngine.onTitleChange` 回调中调用 `tabManager.renameTerminalSession(id, to: title)`

注意：用户手动重命名应优先。方案：TerminalSession 新增 `var isManuallyRenamed: Bool = false`。手动重命名时设为 true，此后忽略 OSC title。用户清空标题时重置为 false（恢复自动跟随）。

```swift
// TerminalEngine.swift
protocol TerminalEngine: AnyObject {
    var onCwdChange: ((UUID, URL) -> Void)? { get set }
    var onTitleChange: ((UUID, String) -> Void)? { get set }
    // ... 其余不变
}

// GhosttyTerminalEngine.swift — init() 中 pwdHandler 之后追加
GhosttyApp.shared.registerTitleHandler(id: registrationID) { [weak self] surface, title in
    self?.handleTitleChange(surface: surface, title: title)
}

// GhosttyTerminalEngine.swift — 新增
private func handleTitleChange(surface: ghostty_surface_t, title: String) {
    for (id, view) in surfaceViews {
        guard view.surface == surface else { continue }
        onTitleChange?(id, title)
        return
    }
}

// deinit 中 unregisterPwdHandler 已同时清理 titleHandlers（GhosttyApp.swift:42）

// ContentView.swift — setupTerminalCallbacks() 或类似位置
terminalEngine.onTitleChange = { [weak tabManager] id, title in
    guard let tabManager else { return }
    guard tabManager.terminalSessions[id]?.isManuallyRenamed != true else { return }
    tabManager.renameTerminalSession(id, to: title)
}
```

### TerminalSession 改动

```swift
struct TerminalSession: Identifiable {
    let id: UUID
    var title: String
    let cwd: URL
    var currentCwd: URL
    var lastActiveAt: Date?
    var isManuallyRenamed: Bool = false  // 新增
}
```

### TabManager 改动

`renameTerminalSession` 保持不变（已有）。手动重命名路径（UI 双击）需额外设 `isManuallyRenamed = true`：

```swift
func renameTerminalSession(_ sessionID: UUID, to title: String, manual: Bool = false) {
    terminalSessions[sessionID]?.title = title
    if manual {
        terminalSessions[sessionID]?.isManuallyRenamed = true
    }
}
```

UI 侧调用改为 `onRename: { tabManager.renameTerminalSession($0, to: $1, manual: true) }`。

### 持久化

`TerminalTabState` 新增 `isManuallyRenamed: Bool`。恢复时传入 `TerminalSession`。

### 验证

- 新开终端 tab，运行 `echo -ne '\033]0;MyTitle\007'`，tab 标题变为 "MyTitle"
- `cd /tmp`，若 shell 配了 PROMPT_COMMAND/precmd 设标题，tab 标题跟随
- 双击手动重命名后，OSC 标题不再覆盖
- 重启后手动命名的标题恢复，自动标题仍跟随

## P1-c：移除 Reveal in Finder，替换为 PathDeck 内定位

### 理由

PathDeck 本身就是文件浏览器。"在 Finder 中显示" = 把用户送去 Finder 看同一个文件，逻辑上自我否定。

### 方案

**右键菜单**（`FileTableView.swift:320-321`）：

- 移除 `addMenuItem(to: menu, title: "在 Finder 中显示", action: #selector(menuRevealInFinder(_:)))`
- 移除 `menuRevealInFinder` 方法
- "复制路径"上移填补空位

**Preview Pane**（`PreviewPane.swift:92-94`）：

- 移除 "Reveal in Finder" ActionButton
- 替换为 "Copy Path"（复制文件路径到剪贴板）

**ContentView.swift:226-228**：

- 移除 `onRevealInFinder` 回调传入

### PreviewPane 接口变更

```swift
// PreviewPane.swift — 替换
ActionButton(title: "Copy Path", icon: "doc.on.doc") {
    if let url {
        NSPasteboard.general.clearContents()
        NSPasteboard.general.setString(url.path(percentEncoded: false), forType: .string)
    }
}
```

`PreviewPane` 的 `onRevealInFinder` 参数移除。`ContentView` 中对应传参移除。

### 验证

- 右键菜单无"在 Finder 中显示"
- Preview Pane 无 "Reveal in Finder"，有 "Copy Path"
- Copy Path 功能正常（粘贴后是完整路径）

## 关键决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 列宽策略 | lastColumnOnlyAutoresizing | AppKit 原生，最小代码量，Finder 同款行为 |
| 垂直 divider 拖动范围 | 100–300pt | 100 最窄可显示标题截断，300 不超过窗口半宽 |
| OSC title vs 手动重命名冲突 | 手动优先，`isManuallyRenamed` flag | 用户意图高于自动行为；清空标题可重置 |
| Reveal in Finder 替代 | Copy Path | 复制路径是文件工作台的高频操作，填补移除留下的空位 |
